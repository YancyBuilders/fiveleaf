# 架构

简体中文 · [English](ARCHITECTURE.md)

FiveLeaf 的 Go 代码由 `main` 包和若干内部包组成，界面用 [MyGo](https://github.com/egoist/mygo) 绘制。Chroma 在后台 goroutine 为代码着色，libghostty-vt 驱动终端，fsnotify 让文件树和快速打开索引跟随磁盘变化。撤销历史、编辑命令和装饰由应用统一管理，因此显示同一文件的各分栏共享文字和历史。以下按源码模块介绍。

<a name="windows-and-commands"></a>

## 窗口和命令

**`main.go`、`ipc.go`、`internal/cli`。** 这几处负责管理窗口。应用可以从三个入口接收目录或文件。`ff` 命令使用应用自己的可执行文件。在 macOS 上，安装的脚本设置 `FIVELEAF_CLI` 再启动该文件。在 Linux 上，可执行文件本身就是命令。`cli.Parse` 读取选项，命令通过数据目录内的 Unix 套接字以 JSON 发送请求。运行中的应用监听该套接字，由主线程上的 `serve` 处理。回复包含要打印的信息或错误。传入 `--wait` 时，等文件关闭后才会回复。应用未运行时，命令会启动它，收到响应后再发请求。如果只传目录或文件，它们会在启动时交给应用，和 Finder 传入的路径一样。Finder 可以把要打开的目录或文件交给应用。带路径启动的第二个 FiveLeaf 实例会转交路径后退出。目录会交给已打开它的窗口，找不到时使用新窗口。文件交给目录范围包含该文件的窗口，命令交给根目录包含命令运行位置的项目。`ff settings` 直接读写全局或目录自己的设置文件。运行中的应用会像处理用户保存一样重新读取设置，因此应用关闭时也可以执行此命令。

**`projects.go`。** `frame` 是一个原生窗口。`desktop` 表示窗口里的一个项目，有独立的 `app`。通常每窗一个项目，启用项目标签页后可把全部项目放进一个窗口，用窗口左侧的栏切换。当前显示的项目会构建界面，其他项目在窗口绘制时处理投递到各自队列的工作。项目被切走时，编辑器会记下滚动位置，和隐藏标签页的处理相同。再次显示时会重新构建文本区。项目元素使用窗口 ID 作为键，避免不同项目使用相同标签页编号时串用状态。打开项目标签页功能会把各项目移到最前面的窗口里，关闭它则恢复每项目一个窗口。

**`app.go`、`commands.go`。** 这两处保存状态和命令。每个项目有自己的 `app`，各窗口共享设置和菜单栏。菜单项在选择它的窗口内运行对应命令。菜单、快捷键和测试使用同一组命令。窗口来到最前面或最近目录发生变化时，应用会重建菜单栏，让 **打开最近的文件夹** 略过当前窗口的目录。

**`internal/settings`。** 应用会在改动后稍等片刻，再写入两个 JSON 文件。用户选的偏好在 `settings.json` 中，窗口、标签页、最近目录和布局存放在旁边的 `state.json`。应用还会监视该目录。检测到自身程序以外的写入时，会从文件读取设置所嵌入的 `Prefs`，由 `main.go` 在主线程应用到每个窗口。窗口和布局沿用应用当前的状态。每帧会检查设置中配置的代码字体和终端字体，发生变化时重新测量。

**`locales`。** FiveLeaf 的界面文字位于 ICU 消息目录 `en.json`、`zh-Hans.json` 和 `ja.json`。`mygo generate` 据此生成 `catalog_gen.go`。每条消息有一个类型明确的函数，返回应用当前语言的文字。视图每帧取值，重新绘制时就会跟随界面语言。菜单和命令面板标题这类预先构建的内容，收到 `App.OnLocaleChanged` 通知后会重建。**查看 → 语言** 写入 `locale` 设置，再交给 `App.SetLocale`。`commandsIn` 按指定语言为命令生成标签，命令面板因此也能匹配英文名称。发送给 Agent 的内容和 Git 自身的输出使用原始文字。

**`internal/keymap`、`keymap.go`。** `keybindings.json` 使用 VS Code 格式，支持注释。应用像监听设置一样监听此文件。编辑器、终端（`OnKey`）、文件浏览器、差异视图、图片和文本字段收到按键时，先通过 `takeKeys` 查询键位表，使组合快捷键的后续键不会被当作输入文字。焦点不在这些地方时，窗口将文件里的键位注册为自己的快捷键。绑定中的命令按 FiveLeaf ID 或 VS Code 名称在下一帧执行。`runCommands` 逐帧执行一串命令，每一步都等先前的编辑和 Git 命令完成。

**`view.go`。** 负责布局。侧栏、分栏和面板在增减视图时使用稳定的键，编辑器据此找回自己的状态。拖动标签页时，窗口传递的是标签页对应的值。分栏的投放目标在拖动时才会显示。

<a name="documents-editors-and-columns"></a>

## 文档、编辑器和分栏

**`document.go`、`columns.go`。** 文档保存文件内容、撤销历史和 Git 标记。编辑器是一个标签页中的文档视图，各自维护选区、滚动位置和绘制缓存。每个分栏持有若干标签页，标签页可以是编辑器或终端。

**`columnlock.go`。** 锁定的分栏即使没有标签页也会保留，自动打开的文件和新终端标签页会使用可接收它们的分栏。`fileColumn` 选择当前未锁定的分栏或上次使用的分栏。如果全部分栏都锁定，就在左侧新建一个工作区。显式拖放和会话恢复直接指定目标分栏。删除空文件分栏时会保留最后一个未锁定的工作区，宽度只分配给其他未锁定分栏，避免锁定分栏在文件关闭时变宽。会话保存每个分栏的锁定状态、上次使用的文件分栏和已有的宽度权重。

每个分栏最多有一个标记为 `transient` 的预览标签页。文件浏览器和搜索通过 `previewFile` 打开文件。如果文件已在某个标签页中，就直接显示那个标签。否则在预览标签的位置显示新文件。旧文档若没有其他标签页使用，会被释放。没有预览标签时会新建一个。以普通方式打开文件、编辑、双击标签页或拖到另一分栏都会保留标签。快速打开中的最近文件只收录这些已保留的标签。点击源代码管理里的提交时，`previewCommit` 通过与文件预览共用的 `previewIn` 在同一位置打开提交。`showCommit` 可以将它保留为普通标签。

输入归到持有键盘焦点的编辑器，同一文档的其他编辑器选区会随文本移动。文本区的内容改变时会自动滚动到光标，因此没有键盘焦点的编辑器会把文本区光标放在当前可见处，另存自己的选区，让滚动位置停在原处。

**`editor.go`、`wrap.go`。** 编辑器把 `TextAreaBufferBase` 放在可横向滚动的容器内。

- **未换行时**，每行高度相同。绘制时把行号画在文本区左侧留白里，使其与文本同步滚动。
- **换行时**，文本区与视图等宽，并通过 MyGo 的 `TrackLines` 报告每行的布局位置。装饰先按未换行时的行内位置计算，再拆到各个视觉行。

只有可见行会应用 `TextRanges` 颜色。颜色在帧之间缓存，并尽可能合并成少量范围。

<a name="editing-and-undo"></a>

## 编辑和撤销

**`history.go`。** 撤销和重做由应用统一处理。缓冲区使用持久化树，每一步只需很少的开销就能保留编辑前的文本。帧开始时检测文本区的输入，连续输入归入上一步，直到输入暂停或光标移动。

**`editing.go`、`autoclose.go`。** 编辑命令是作用于文档和选区的函数。按键先由这些命令处理，等下一帧选区确定后执行。自动补上的括号会跟在键入括号的编辑之后，两次修改合为一步撤销。

**`vim.go`。** Vim 普通模式和可视模式的按键事件进入 `editorKey`，在那里读成命令。命令引起的模式切换立即生效，使后续按键能按正确模式解释。命令本身和其他编辑一样在下一帧执行。文字输入直接走文本区的输入法通道，绕过 `HandleInput`。因此普通模式将文本区设为只读，隐藏它自己的光标并另外绘制方块光标。修改命令进入插入模式时，随后的输入并入改动的撤销步骤。`history.group` 会保持这一组打开，直到按 `Esc`。

<a name="decorations"></a>

## 编辑器装饰

**`decorations.go`、`selection.go`、`sticky.go`。** 绘制文字周围的内容，包括缩进参考线、括号配对、同词高亮，以及选区及其中的空白字符。

- 只针对可见行计算装饰。文本、光标或视图发生变化时才重算。
- 以和文本区相同的规则测量文本并定位装饰。制表符使用平台的制表位。
- 粘滞行和面包屑由缩进推导，各种语言都可使用。

<a name="image-viewer"></a>

## 图片查看器

**`viewer.go`。** 图片标签页持有查看器。位图在主线程之外解码，按查看器保存的缩放和偏移在棋盘格背景上绘制。

SVG 预览用查看器替代它对应的编辑器画面。每次编辑后稍作等待再解析，保留最近一次成功解析的图片。文本区继续存在，只是暂时隐藏，因此编辑器的位置得以保留。

<a name="markdown"></a>

## Markdown

**`markdown.go`、`markdownsync.go`。** 每次编辑后稍等片刻，goldmark 在后台把 Markdown 解析成块，由 `markdownRow` 逐块绘制。实时预览也用它来绘制渲染块。

**`markdownlive.go`、`markdownliveview.go`。** 实时预览直接在编辑器的文本区上应用样式，与 Obsidian 的方式相似。每次编辑后，后台解析会找到若干 Unicode 字符区间。这些区间包括控制标题字号或粗体字重的样式、Markdown 标记，以及项目符号、任务框、图片或公式等对象。光标或选区触及标记所覆盖的内容时，才显示该标记。对象绘制在第一个字符的位置，其余字符隐藏。这些区间作为 MyGo 的 `TextRange` 交给文本区，只处理视图周围的行。

新解析结果出来之前，上一次解析结果用 `liveDoc.mapTo` 跟随其后的编辑。它从文本两端比较，改动前的区间留在原位，改动后的区间随之移动。在样式末尾输入时，样式会扩大，标记范围则停止在原处，避免输入落进隐藏标记。`liveDoc.visit`、`eachDeco` 和 `eachBlock` 只移动当前帧显示的区间、卡片和块。长笔记里的单次按键和短笔记的开销相当，`BenchmarkLiveMapTo` 测得映射约需 50 µs。勾选任务框后仍显示为任务框。

第一帧在主线程快速解析，暂缓处理图片、公式和块。表格、图表和独立公式使用块。`TextBlocks` 为其源代码行预留渲染高度，`markdownRow` 绘制块并盖在对应行上。光标进入块时展示源码。解析使用 `markdownCache.blocks` 复用与上次绘制时源文完全相同的块，只重绘修改过的部分。根据 `BenchmarkParseLive`，解析一篇含大量渲染块的 250 KB 笔记约需 13 ms 和 30 MB，其中图片或公式由区间通过指针持有。

每个块为绘制结果预留空间。如果源代码更高，例如一条短公式的定义，则使用源码高度。光标进入或离开块时，`liveIn` 会在两种高度间过渡，光标折返就从当前高度继续。多出来的高度由下方空白行吸收。如果下一行紧接文字，就将块最后一行的最后一个字符作为对象绘制并增加行高，使下面的文字平滑移动。块完成测量后淡入。项目符号和任务框保留源码占用的宽度，光标到达时在原有位置显示源码，整行位置保持稳定。

正在加载的网络图片先显示 `livePicture` 卡片。图片到达后，卡片占用的空间过渡到图片大小，并在同一位置淡入图片。`liveHovered` 根据文本区报告的指针位置找到下方链接，让下划线逐渐显现。代码块用绘制在行底的卡片呈现，高亮器通过 `liveState.codeColors` 只为代码文字着色。每次都会解析整篇笔记，并复用上一次的缓存。`BenchmarkMarkdownReparse` 中，按键后有缓存约需 13 ms，无缓存约需 550 ms。

<a name="git"></a>

## Git

**`internal/git`。** 这个包通过 `git` 命令处理操作。它用 `git rev-parse` 找到工作树，保留目录传入时的路径写法，经过符号链接的路径也能与编辑器匹配。它用 `git status --porcelain=v2` 读取状态，执行暂存、取消暂存、丢弃、提交、查责、切换、获取、拉取和推送。命令在 `GIT_TERMINAL_PROMPT=0` 下运行，SSH 使用批处理模式，因此需要交互提示的登录会直接失败。

**`git.go`、`scm.go`。** 窗口保存当前状态。文件树发现变化、保存文件或运行 Git 命令之后、窗口取得焦点时，以及每隔 5 秒，都会在后台读取状态。与上一次相同的状态会被丢弃，复用据此生成的数据。每次不同的状态只生成一次源代码管理的分组和行，差异视图也只在新状态下重新列文件。`HEAD` 或其上游移动时会重新读取最新提交。每 1.5 秒还会检查索引、`HEAD` 和 `FETCH_HEAD` 的时间。在终端提交或检出会改变这些时间，文档随后重新比较各行。源代码管理视图的命令在后台运行，每个命令完成后重新读取状态。

**`internal/gitmarks`、`internal/linediff`。** 用 `git show` 读取 `HEAD` 的文本，每次编辑后在后台用 Myers 差异算法比较各行。对一个 100,000 行文件中的少量编辑，比较大约需要 0.25 ms。差异生成改动块，也就是成批替换的行。边栏标记、快速查看框和差异标签页都使用这些块。

**`hunks.go`。** 还原改动块会编辑文档。暂存时，索引可能已经不同于 `HEAD`。因此先比较索引文本和编辑器内容，再应用本次比较中与所选改动重叠的改动块。最后用 `git hash-object` 和 `git update-index` 写入结果。这一过程直接计算新内容，省去生成补丁和模糊匹配。

**`diffview.go`。** 差异标签页在可双向滚动的窗格里自行绘制各行。并排视图需要给另一侧独有的行留出空白，普通文本区无法这样排版。仅绘制可见行，两侧分别使用自己的高亮器，也只为可见行计算词级改动。工作树一侧可以就地编辑。输入、撤销和保存状态均属于同一文件文档，与文件编辑器共享，实现在 `diffedit.go`。其他侧是只读的。双击可打开文件编辑。

同一个差异标签页显示当前状态中的所有文件，包括已暂存和未暂存文件。文件逐个读取和比较，同时最多处理四个，范围为距离可见区不超过一个视口高度的文件。读取完成、展开折叠区、更换布局或换行时宽度改变，`diffrows.go` 才重新布局。可见区上方的文件读完并增高时，选中行会保持屏幕位置。没有选中行时，固定最上面一行。未改动的行折叠成间隔，用新一侧的起始行作为键，使输入时展开的间隔继续保持展开。连续改动前会放一个标题。换行后某行可能占多行高度，因此保存每行顶部坐标，用二分查找定位给定位置的行。`diffpaint.go` 绘制可见行。

`diffhunks.go` 在差异视图中暂存、取消暂存或丢弃成批改动，方式与 `hunks.go` 从边栏暂存相同。它会重新读取索引和文件，在最新内容中重新定位这些改动，再用 `git hash-object` 写入结果。丢弃时，有打开的文档就编辑文档，否则直接写文件。

提交标签页使用同一视图的另一种模式。它用 `git diff-tree` 列出相对第一个父提交修改的文件，用 `git show` 读取两侧内容，并在文件前面放上提交说明卡片。提交里的文件内容固定，只需读取一次。

**`search.go`。** 文件搜索用若干 goroutine 读取快速打开索引中的文件。打开的文档有未保存改动时，使用文档文字。每次搜索有自己的编号，先前搜索迟到的结果会被丢弃。找到的文件每隔 60 ms 返回一批，按路径排序。文档被编辑，或文件树报告某个文件改变后，单独重搜该文件并替换它的结果。应用会监听结果所在的目录，即使目录在文件树中处于折叠状态，也能发现磁盘上的变化。替换时先用当前文本重新找匹配。已打开文档的改动合为一步撤销，未打开的文件在后台写入。`internal/workspace/glob.go` 计算包含和排除范围。

**`branchpicker.go`。** 切换分支使用与快速打开类似的选择器。打开时用 `git for-each-ref` 读取本地及远程分支，最近提交过的分支排在前面。筛选使用与文件相同的模糊匹配器。

**`recentpicker.go`。** 打开最近文件夹使用同一类选择器，从设置中读取近期目录。`⌃R` 注册为视图快捷键。焦点在终端时，这个按键由终端接收。

**`blame.go`。** 光标在一行停留 350 ms 后，`git blame --contents -` 会查询编辑器中该行的提交来源。查询也使用未保存的改动。

<a name="internal-packages"></a>

## 内部包

**`internal/highlight`。** Chroma 的词法分析在后台 goroutine 执行。文件不超过 6,000 行时分析整个文件，超过时分析视图附近的范围。文件刚打开时，视图周围的行优先分析。

- **编辑后**，只重新分析改动周围的行。从改动上方、跨行字符串和注释之外的位置开始。改动前各行的结果与原来一致时才采用这次分析。改动下方有几行恢复一致时就停止。在 6,000 行 Go 文件中，单次按键的分析耗时由 170 ms 降到约 0.7 ms。
- **输入暂停后**，再分析整个范围并纠正与上次不同的行，涵盖无法仅靠行周围的 token 判断状态的词法分析器。
- **分析完成前**，因编辑而移位的行会保留原色，只有一次插入或删除的行也会保留。通过其他方式改动的行显示为纯文本，避免旧颜色落到错误位置。

**`internal/workspace`。** 目录展开时读取，通过 fsnotify 监听，短时间内多次变化合并处理。包中也维护快速打开的文件索引和模糊匹配器。远程文件树优先在主机上运行 `inotifywait`。如果主机没有该命令，就每隔 3 秒通过一次往返读取文件浏览器显示的目录，并查询打开文件的状态，只报告相较上次发生的变化。

<a name="remote-folders"></a>

## 远程目录

**`internal/remote`。** 远程文件有自己的路径格式 `/ssh:host/path`。`filepath` 按普通路径处理它，因此文档、文件树、Git 和设置可以和本地路径一样保存它。连接主机时创建 SSH 主连接（`ControlMaster`），每条命令都经由它。`BatchMode` 让连接无需等待密码输入。每条命令是一个短 POSIX shell 脚本。主机上的 `sh` 从 SSH 送来的输入中先读长度，再读脚本，绕过可能是 fish 的登录 shell。其余输入留给脚本，例如传入文件内容。它用 `[ -d ]` 循环读取目录，使用主机上可用的 GNU 或 BSD `stat` 获取状态，通过 `head -c` 读取单个文件，或用 tar 流同时读取多个文件。写入时先将全部内容写到临时文件，再复制到目标。`config.go` 列出 `~/.ssh/config` 中的主机。

**`internal/vfs`。** 提供编辑器使用的文件系统接口。每个函数接收本地或远程路径，执行与 `os` 中同名函数相应的操作。`Command` 在目录所在机器的该目录中运行程序。`internal/git`、`gitmarks` 和索引据此在主机上执行 `git` 和 `find`。远程路径需要网络往返，应用在主线程之外发起调用。

**`remote.go`、`remotesearch.go`。** 每个项目跟随其目录主机的连接。远程文档会立即以空白、只读状态打开，内容在后台读取，保存也在后台完成。保存后记录 `stat` 返回的文件信息。监听器再报告这次变化时，只需查状态。主机未连接时，文档保持只读，横幅提供重连入口。重连后重新读取文件树、打开的文件和状态。文件搜索在主机上用 `rg` 或 `grep` 找出可能匹配的文件，再读取这些文件并在本地按相同规则匹配，使结果与搜索本地文件一致。

<a name="plugins"></a>

## 插件

**`internal/plugin`。** 插件放在 `~/.fiveleaf/plugins` 中，每个插件一个目录，包含 `plugin.json` 和可选的入口模块。用户还可以向 `~/.fiveleaf/scripts` 添加脚本。应用从 `extensions/index.json` 内嵌备用目录。`Registry` 读取已安装插件的清单，无需运行插件即可知道它贡献的功能。发生插件声明的事件时才启动它，例如运行其命令、打开某种语言的文档或打开视图。每个运行中的插件有自己的 [moejs](https://github.com/MoeForge/moejs) 运行时和事件循环，在独立的 goroutine 里执行。包中只有 `runtime.go` 导入 moejs。`prelude.js` 在一组宿主函数之上构建 `fiveleaf` 模块，应用通过它绑定的分发函数调用插件，双向数据使用 JSON。JavaScript 连续运行 10 秒未让出执行时，监控器会停止它。插件占用 256 MiB 时，moejs 的限制会将其停止。连续停止三次的插件停用至重新加载。允许导入插件自己的文件和 `fiveleaf`，`eval` 已关闭。应用监听插件目录，文件变化的插件下次使用时重新启动。`install.go` 用 `git` 克隆、更新和移除插件，在 `plugins.json` 中保存来源。`pack.go` 把插件导入的 npm 包复制到 `vendor/`。`cli.go` 提供 `ff plugin`。

**`plugins.go`、`pluginapi.go`。** 应用一侧提供 `pluginHost`，由注册表作为 `Host` 调用。插件调用在 goroutine 上运行，再通过 `a.post` 交给主线程上的前台窗口。两端由此各自推进，避免阻塞界面帧。文档文字按快照读取，编辑请求带上生成它时使用的版本。若文档此后已改变，就拒绝该请求。插件命令加入 `commandsIn`，供菜单、命令面板、键位和 `ff run` 使用。插件快捷键使用 FiveLeaf 命令和 `keybindings.json` 都未占用的按键。`pluginevents.go` 将文档与上帧比较，把打开、改变、保存和关闭通知给插件，并启动将相应事件声明为激活条件的插件。

**`pluginui.go`、`pluginviews.go`、`plugintheme.go`、`pluginsnippets.go`。** 插件可以提供状态项、诊断、格式化器、视图、预览、WebView、主题、语言和片段。诊断由 `editor.go` 画成下划线，并显示在 **显示问题** 中。`saveDoc` 等待格式化器的上限为 1.5 秒。插件视图是用 MyGo 控件在侧栏绘制的节点树，预览占用查看器的位置，网页通过带消息桥的 `ui.WebView` 显示。插件主题在 FiveLeaf 调色板上叠加颜色，VS Code 主题会映射到这些调色板。语言通过 `highlight.LexerName` 注册。`prefsplugins.go` 提供设置窗口的插件页面。

**`internal/lsp`、`lsp.go`。** 打开某个插件所声明语言的文档时，会通过 `vfs.Command` 为目录启动语言服务器。SSH 工作区因此会在远程主机运行服务器，URI 也使用主机路径。客户端通过服务器的标准输入输出进行 JSON-RPC 通信，在文档变化时发送完整文字，并接收诊断、悬浮信息、定义、补全和格式化结果。

<a name="theme"></a>

## 主题

**`theme.go`** 内嵌 FiveLeaf 的浅色和深色调色板，并将所选配色应用到窗口、代码和终端。其他主题分别由插件提供，自适应主题会一起提供两套配色。The Matrix、Purple Gold 和万圣节主题始终使用深色原生窗口。Claude、Qoder、Grok Bot 和 Cursor 各有浅色和深色配色，跟随 `appearance` 设置。Qoder 一类调色板定义了 `card` 圆角，`workbench.go` 将编辑器和底部面板布置在带颗粒纹理的外框卡片里。外框各部分之间省去分隔线，分隔条在指针附近提亮。

`rain.go` 在欢迎页背后绘制 The Matrix 的数字雨，位置只由时间决定，每 70 ms 前进一步。`mascot.go` 把主题角色放在欢迎页和状态栏。姿势也按时间计算，只在下一次姿势变化时请求绘制。`clawd.go` 用网格绘制 Claude 的角色。`qoduck.go` 用矢量图形绘制 Qoder 的鸭子，`mascot.go` 按正在进行的工作给状态栏里的鸭子选择道具。`grokbot.go` 也用矢量图形绘制 Grok Bot 的脸。`halloween.go` 用网格绘制万圣节主题的南瓜、坩埚和蝙蝠，`rabbit.go` 同样用网格绘制 The Matrix 的白兔。Cursor 和 Purple Gold 没有角色。`clauding.go` 按 Claude Code 欢迎框的样式绘制 Claude 的欢迎页，并在 Git 工作时绘制状态栏转动指示。字符、文字上的光影和秒数都按时间计算，每 120 ms 前进一步。它还负责覆盖在窗口上的对话框和编辑器浮层的样式，使它们出现时淡入。

设置文件里的 `themes`、`~/.fiveleaf/themes` 中的文件或插件的 `contributes.themes` 都可以提供主题。`plugintheme.go` 在原调色板上覆盖 `colors`、`syntax`、`ansi`、`metrics`、`mono`、`sentence`、`card` 和 `grain`。`paletteFor` 用统一方式返回调色板，窗口其余部分可以照常使用。参见[主题文档](THEMES.md)。

<a name="performance"></a>

## 性能

以下数字取自在 M 系列 Mac 上运行的测试。

- 打开一个 100,000 行文件约需 20 ms。
- 滚动和输入每帧低于 2 ms。打开查找时约为 3 ms。
- 在 6,000 行文件里按一次键后重新高亮，耗时低于 1 ms。
- 快速打开搜索 100,000 个路径约需 1.5 ms。
- 打开和关闭命令面板共需约 13 ms，各占一帧。

`budget_test.go` 的 `TestBudgets` 为帧开销设置预算，为较慢的机器留出数倍余量。它覆盖空闲、滚动和输入、打开查找时输入、快速打开、命令面板、在 2,000 个会话中滚动、悬停和筛选，以及以最大速度输出的终端。CI 会在 macOS 上为每个拉取请求运行此测试（`FIVELEAF_BUDGETS=1`）。
