# Agent 聊天、圆桌会议和代码审阅

简体中文 · [English](AGENTS-ACP.md)

FiveLeaf 在原生 MyGo 界面中运行外部 Agent Client Protocol（ACP）适配器和命令行 Agent。各 Agent 管理自己的模型、账号和工具。FiveLeaf 提供独立聊天、项目圆桌会议、编辑器上下文、ACP 权限选择和改动审阅。

<a name="start-a-chat"></a>

## 开始聊天

1. 打开本地项目目录。
2. 在 **设置 → 插件** 中安装并启用相应的 Agent 插件。要注册自定义程序，请打开 **设置 → Agent → 添加自定义 Agent…**。先用该 Agent 常用的命令行登录。适配器声明支持登录时，也可以点击 **登录**。
3. 打开侧栏的 **Agent 会话**，选择 **新建聊天**。点击旁边的箭头可以选择已注册的 Agent。
4. 输入消息并按 `Enter` 发送。按 `Shift+Enter` 换行。

输入框和侧栏的选择器会在 Agent 名称前显示图标。右侧一列显示实时状态。带圆圈的勾表示在线，断开的链接表示离线，脉动表示正在工作，三角警告表示连接失败。将指针停在一行上可读到状态说明。左侧的勾标记当前会话。即使另一个 Agent 仍在回复，也可以点击一行切换到对应会话及其草稿。**设置 → Agent** 列出你添加或覆盖配置的 Agent，可在这里启用或停用。**Agent 会话** 上的角标表示有待处理的 ACP 权限请求。右键点击该入口，选择标为 **需要授权** 的会话。

侧栏的 **Agent 会话** 单独展示 Claude Code、Codex、Pi、Qoder、Grok、插件及圆桌会议的本地记录。命令 `view.sessions` 可以打开它，工作区里的聊天会继续显示。右键点击侧栏的 **Agent 会话**，可以在已经打开的聊天标签页间切换。双击某次 Agent 聊天，或选择 **恢复**，即可在会话原属项目的编辑器中接着聊。支持恢复的适配器会跨轮次保留原会话 ID。其余 Agent 使用本地对话记录的节选作为上下文。通过 **使用其他 Agent 接续…** 可以选择接收该节选的 Agent。

聊天在工作区标签页中打开。聊天工具栏的第一个按钮 **新建聊天**（`+`）会新开标签页，**向右拆分** 会在当前聊天旁打开独立的新聊天。两个会话可以使用同一个 Agent。每个标签页用第一条提问命名，并各自保留草稿和回复。项目仍打开时，可用 **重新打开已关闭的标签页** 恢复刚关掉的聊天。

从 **Agent 会话** 恢复 Codex 时，项目和 Agent 配置匹配即可重新打开已有聊天，保留其中的草稿和待发消息。

打开聊天会自动连接 ACP 适配器，切回已打开的聊天会复用连接。点击 **发送** 时才会提交草稿和导入的历史。聊天按接收顺序显示适配器的启动和重连输出。命令行程序在第一条消息发出时启动。**停止** 会请求取消当前回复，等待原请求结束期间连接保持打开。在连接准备期间停止，未发出的消息会回到输入框，连接继续准备。等待期间可点击 **重新连接** 主动重启适配器。进程退出后，也可直接发送下一条消息建立新连接。支持恢复的 Codex 适配器会在相同配置下重新打开原会话。对话记录和草稿会保留。关闭项目或应用会取消其中的所有对话。
如果原 Codex 线程仍被其他 Codex 客户端占用，可选择 **在新线程中继续**，对话记录和草稿会保留。
仅在适配器明确报告需要认证时显示登录选项；适配器公布登录方式本身不会显示登录按钮。

ACP 单聊默认持续等待回复。如果设置了回复超时，发送问题后按无进展的时长计时。收到新输出或工具更新时重新计时，等待授权时暂停。达到时限后会使用与 **停止** 相同的方式取消。连接准备有独立的时限。回复中断后，已发消息和收到的部分输出保留在对话里。可以从原消息选择 **恢复到输入框**，编辑原文和附件后再发送。

回复期间可用 **排队发送** 暂存一条追问。本轮正常结束后会发送追问。停止、失败或断连会暂停队列。可在输入框空白时选择 **编辑待发消息** 取回文字和附件，也可移除待发消息。

回复会渲染 Markdown 列表、表格、引用和围栏代码块，并使用当前主题的语法配色。代码块会显示语言，长行可在块内横向滚动，也可以点击 **复制代码**。**复制消息** 会保留原始 Markdown，包括超出显示上限的文字。圆桌回复使用同一套渲染方式。

工具调用会出现在对话里实际发生的位置，连续调用可按组折叠，也可逐条查看结果。失败的调用默认展开详情。展开后可查看适配器提供的输入和输出，包括流式命令输出和单独返回的工具结果。命令运行时会临时展开，完成或出现后续输出后自动收起。可以复制工具输出，折叠后仍可打开改动审阅。

收到的推理内容以独立颜色显示，流式输出时展开，继续回复后折叠。用左侧小箭头可展开或收起，也可从回复末尾点击 **查看推理过程** 返回本轮。Codex 的进度更新有独立标签，回合完成后标出最终回复。后续输出或切换标签页时，会保留手动选择的展开状态。向上滚动可以停在正在阅读的位置。点击 **回到最新** 可回到最新输出并继续跟随。
推理内容使用比正式回复小一号的灰色字体。

ACP Agent 发来计划时，输入框上方会出现 **待办列表**，并随任务进度更新。标题会显示已完成的任务数量。点击标题可折叠或展开列表。高度较小的分栏会默认折叠。

在 **设置 → Agent → 对话设置** 中可以配置当前项目里最近获得焦点的聊天。你可以修改系统提示、设置要重放的近期消息数（1–100 条，默认 10 条）或清空对话记录。每个分栏里的聊天各自管理这些设置。重放只包含已完成轮次的用户消息和公开回复。Codex 和通过适配器原生恢复的聊天会把后续消息发送到原会话，由 Agent 管理历史。普通 Codex 聊天在重连或修改系统提示后新开线程时会重放近期消息。其他新 ACP 聊天每轮新建会话并重放近期消息。发送前会应用所选模式和模型。如果所选项不可用，会显示错误。**清空对话** 清除所选聊天的对话记录，草稿、角色和上下文设置会一并保留供下次使用。

在草稿中输入 `@`，可按名称或路径搜索项目文件。选中文件后，会把名称插入草稿并将文件作为附件。以 `/` 开头可浏览当前 Agent 的命令。列表先列出会话命令，再列出 Pi 的 `skill:` 项和 Codex 的 `$` 技能。可以按名称或说明搜索全部条目，使用方向键选择并按 `Enter` 或 `Tab` 确认，按 `Esc` 关闭。添加参数后，把命令发送给当前会话。

Agent 通过 ACP 提供模型、思考强度或模式选项时，可以用 `/model`、`/thinking` 和 `/mode` 打开对应选择器。可以选择一个值直接应用，也可以带上准确的值发送命令，例如 `/thinking high`。如果 Agent 已声明同名斜杠命令，则执行 Agent 定义的行为。Pi 的 `/settings`、`/tree` 和 `/scoped-models` 会在 Pi 终端中打开对应界面。

输入框固定在对话底部，包括空聊天。它随文本换行增高，达到高度上限后可滚动。底部提供模型、Agent 和发送控件。较宽的 Agent 页面还会显示 ACP 会话使用的工作区目录，悬停可查看完整路径。

在输入框末尾粘贴超过 20 行或 8 KiB 的文本会生成可折叠的附件。可展开预览或移除。编辑时，该片段和此前的片段会按顺序移入输入框。发送时会把其余附件的原文附在输入内容后。查看较早的消息时，待授权请求仍显示在输入框上方。

点击聊天工具栏或独立窗口标题栏里的气泡，打开 **会话说明**。拖动卡片标题栏可在聊天内移动它。输入或滚动时卡片会保持打开，切回标签页时会回到原位置。在当前聊天中，点击 **×**、再次点击气泡或按 `Esc` 都可关闭。**变更** 显示当前仓库新增和删除的总行数。点击该行可打开仓库差异。

在同一张卡片中选择 **导出为 Markdown…**，可保存本次聊天中已发送的消息和公开回复。文件包含已加载的历史以及打开保存对话框时已经收到的回复文本。

**来源** 按聊天分别记录。它列出已添加的文件和选区、导入的历史对话，以及 Agent 工具明确报告的资源。选择附件文件可重新打开，或点击 **查看全部来源** 展开清单。输入框里的 **+** 和添加文件按钮可打开文件选择器。也可以把文件拖入输入框，或粘贴已复制的文件和截图。将指针移到缩略图或名称上可预览，再移入预览区域可滚动查看所附文本或长图。移开指针或按 `Esc` 可关闭。文本预览包含编辑器尚未保存的改动。ZIP 显示归档条目。PDF 通过 Poppler 或 macOS 快速查看显示第一页，后者也可预览受支持的 Office 文档。其余二进制文件显示开头的字节。点击附件旁边的 × 可移除。点击 **发送** 会提交文本快照，或图片、PDF 和二进制文件的本地路径。也可以单独发送附件。

连接 ACP Agent 后，打开输入框里的模型按钮，可以选择该 Agent 公布的模型。搜索可匹配名称、ID、说明和分组。左侧栏按适配器提供的分组筛选，缺少分组时按模型 ID 中的提供方前缀归类。**最近** 显示在本次聊天选择过的最多八个模型，**新建聊天** 和重连时继续保存在内存中。用上下方向键浏览结果，按 `Enter` 选择，按 `Esc` 关闭。勾号标记当前模型。所选模型在该对话内优先于角色保存的模型，并跨后续轮次、**新建聊天** 和重连生效。角色和 Agent 的默认模型分别管理。切换失败会保留原选择和草稿。会话空闲时可更换模型。

紧凑的模型按钮显示模型名，悬浮提示显示完整 ID。选择器在草稿上方打开，选好模型后仍保持打开，方便接着调节思考强度。如果 Agent 公布了思考强度选项，模型列表下方会出现滑块。点击或拖到对应级别，也可以先聚焦滑块，再按方向键、`Home` 或 `End`。界面只显示当前模型支持的级别，名称使用英文。提供方默认值显示为 **Provider default**，并保留适配器公布的 `off` 或 `auto` 选项。每个级别使用不同颜色。关闭选择器、窗口失去活动状态或启用减少动态效果时，流动高光会暂停。Pi 会先确认所选强度再使用，后续提问会在完成模型设置后重新应用该强度。其余 Agent 模式仍可从输入框菜单选择。

输入框上边缘的细进度条显示适配器报告的上下文占用。左端上方是占用百分比，右端上方是总容量，如 `1M`。进度条两端位于输入框的圆角内。将指针停在任意位置可查看精确的 token 数。点击可打开 **上下文** 详情，查看精确数值、百分比、各类内容的估算值和剩余空间。剩余空间等于总容量减去报告的用量。未上报的容量显示为 `—`。数值随适配器的报告更新，包括回复结束后才到达的报告，新建会话或断开时重置。首次请求前，系统提示词、skills 和工具定义尚未计入。Codex 显示最近一次请求的输入上下文，不含本轮的生成内容。Pi 的容量取自模型目录的 `contextWindow`，不是 `maxTokens`。

对于 Pi，进度条还会标记当前会话加载的配置所指定的压缩阈值。默认预留 16,384 个 token，支持逐模型覆盖和关闭压缩。阈值标记随当前模型的上下文容量定位。详情单列预留空间，已用上下文另行统计。摘要还会显示距离触发压缩有多少 token。启动新的 Pi 会话时会刷新配置，包括后续轮次和重连。

Codex 会在当前线程中自动管理上下文压缩。**上下文** 详情会显示 Codex 上报的压缩状态。如果适配器提供 `/compact`，也可以发送该命令手动压缩当前线程。

ACP 目前上报总占用。详情会估算可见的对话内容，无法取得的内部分类标为 **未上报**，其余占用归为 **未分类上下文**。任务进度和累计 token 计费分别统计。

<a name="other-acp-agents"></a>

## 其他 ACP Agent

下表中的连接都有对应的 [Agent 插件](#agent-plugins)。手动注册时，选择 ACP 协议并使用相同的启动命令。

| Agent | 命令 | 参数 |
| --- | --- | --- |
| OMP | `omp` | `acp` |
| Codex | `npx` | `-y @agentclientprotocol/codex-acp@2.7.0` |
| Claude Code | `npx` | `-y @agentclientprotocol/claude-agent-acp@0.107.0` |
| DSH | `dsh` | `--profile acp` |

OMP 和 DSH 直接提供 ACP。Codex 和 Claude Code 适配器需要 Node.js，首次连接时可能会下载适配器。Codex 优先使用已经安装的 CLI，找不到时使用随适配器打包的 CLI。显式设置的 `CODEX_PATH` 优先级最高。Claude Code 适配器自带 CLI。各连接使用相应 Agent 已有的认证和模型提供方配置。DSH 的 ACP 配置可以与桌面配置不同。

模型和思考强度选项取自当前连接的适配器。即使协议值为空，也会保留提供方默认的思考强度选项。上下文百分比按适配器报告的占用和容量计算。不同 Agent 即便使用相同模型，结果也可能不同。用量上报前，指示器显示未知。Pi 的压缩阈值和预留空间仅用于 Pi。其他 Agent 可上报各自的压缩策略。

另有一项可选的真实连接检查，可通过 FiveLeaf 界面验证这些适配器。运行 `go test -tags agentintegration -run '^TestAgentLiveWorkflow$' ./cmd/fiveleaf`，并将 `FIVELEAF_AGENT_LIVE_CONFIG` 指向包含 `agents` 数组的私有 JSON 文件。每项要提供 `id`、`name`、`server`、两个可用的模型 ID（`model` 和 `alternateModel`）、`replyMarker` 及 `thoughtHigh`。设置 `restoreDefault` 可以跨两次回复检查值为空的提供方默认思考强度。为每个服务器配置隔离的 Agent 状态。检查会在空的临时工作区里发出真实模型请求。如果 Agent 请求调用工具或授权，检查会失败。

<a name="configure-and-use-roles"></a>

## 配置和使用角色

在 **圆桌会议 → 邀请成员** 中选择内置或已保存的角色。未绑定的内置角色会使用可用的 Agent。如需指定 Agent，请在设置中绑定。如果命令行 Agent 的参数包含 `{model}`，要为该角色同时指定该命令行 Agent 和模型 ID。

| 内置角色 | 可以交给它的工作 |
| --- | --- |
| 代码探索者 | 从入口追踪相关文件和符号，进行只读分析。 |
| 规划者 | 把改动拆成有先后顺序的步骤，为每步给出验收检查，保持只读。 |
| 实现者 | 在约定范围内完成改动，并报告通过的检查。 |
| 测试工程师 | 为正常和失败情形编写测试，保留生产代码。 |
| 代码审查者 | 只读检查回归问题，给出文件位置和触发条件。 |
| 诊断者 | 区分证据和假设，提出下一步检查，保持只读。 |
| 文档作者 | 更新文档，并对照实现核验示例。 |
| 需求分析师 | 把请求转成可观察的验收标准，覆盖典型场景和边界场景。 |
| 交互设计师 | 用键盘和窄窗口各走一遍流程，找出用户会卡住的位置。 |
| 兼容性维护者 | 在旧设置和插件的副本上检查升级和恢复。 |
| 圆桌主持人 | 总结共识和分歧，再交接问题或提出下一步检查。 |

每位成员会收到角色提示词和圆桌对话。

打开 **设置 → Agent → 角色列表**，或在 **邀请成员** 旁选择 **配置角色…**。点击角色旁的铅笔可以编辑 Agent、模型或提示词，再选择 **保存**。Agent 列表包含已启用的插件。可以选择已公布的模型，也可用 **加载模型** 查询 ACP 适配器，或手动输入模型 ID。模型留空时使用 Agent 的默认值。

列表会预览角色实际使用的提示词的第一行。**添加角色…** 创建一个命名角色。**复制角色** 会打开所选角色的提示词、Agent 和模型的可编辑副本，也可以选择 **当前 Agent**。点击 **保存** 可把副本加入列表和圆桌邀请选项。

在预设角色上选择 **恢复默认**，会还原为当前 Agent、其默认模型和本地化的提示词。**恢复所有预设角色默认值** 会重置列表中的所有预设角色。两项操作均可 **撤销**。同一列表也可以编辑、重命名和移除自行创建的角色。

通过 **导出角色…** 和 **导入角色…** 可在不同配置间共享角色。Agent 也可以用 `ff roles import -` 或[本地角色 API](SETTINGS.zh-CN.md#share-roles-and-create-them-from-an-agent)批量创建角色。

ACP 角色会在发送前选择所请求的模型，包括后续轮次中新建的会话。适配器必须通过会话配置选项或旧版模型列表提供模型选择。模型不受支持或切换失败时，请求会停止，草稿会保留。

命令行 Agent 可在参数数组中用字面量 `{model}` 配置平常使用的模型参数。例如，对兼容的 CLI 使用 `args: ["--print", "--model", "{model}"]`。占位符只在参数里替换，进程直接启动。角色指定了模型但参数没有对应占位符，或参数有占位符但角色模型留空，都会在命令启动前报错。要让某些角色沿用 Agent 原有的模型参数或默认模型，请给它们单独定义一个命令行 Agent，省略占位符。

编辑角色会断开使用旧配置的连接，并保留历史和草稿。Agent 缺失或停用时，对应角色仍会列出，但暂不可用。在 `settings.json` 中重命名已保存的角色会产生新的邀请对象。先前的消息保留原发言者的名称。

<a name="hold-a-roundtable"></a>

## 开展圆桌会议

在本地项目中选择 **Agent 会话 → 圆桌会议**，可在文件旁打开会议标签页。侧栏的 **Agent 会话** 会显示该项目的会议。点击一行可切换会议，也可以选择 **新建圆桌**，输入主题并邀请成员。可在会议简报中填入问题、约束或期望结果。
**创建并开始** 会立即分派第一个任务。**创建圆桌** 会先打开会议，把简报放入输入框供你编辑。已保存的会议和聊天一起出现在 **Agent 会话** 中。
选择 **使用模板…**，可用方案评审、故障诊断或实现验收模板预填成员和简报。表单会保留当前的主题、主持人和你编辑过的简报。创建前可以调整简报和邀请名单。每个角色使用它绑定的 Agent 和模型。
选择 **所有 Agent → 会议记录** 可筛选出会议。按主题或成员搜索后，双击会议或按 `Enter`，即可打开会议记录。

可以邀请内置角色、自定义角色或单独的 Agent。即使两个角色绑定了同一个 Agent，也会作为独立成员发言，各有自己的指令和模型。成员列表显示每个角色绑定的 Agent。成员会收到主题、名单和本组近期公开发言。ACP 成员可继续使用编辑器权限选择和工具差异视图，命令行成员则返回捕获的输出。

创建会议时选择主持人。指定圆桌主持人角色后，它会阅读主题、分派工作并审阅各成员的发现。将指针停在会议名称下方的标记上，可以看到当前主持人。

要自行主持，打开 **协作** 并选择 **我来主持**。你输入的消息会作为会议发言。用 `@` 可以请某位成员回复一次，也可以发布自己的结论。两轮之间，可以右键点击主持人并选择 **移出本群**，由你接过主持。需要时在 **协作** 中选择原主持人即可将其请回。重新打开会议时会恢复该会议的主持人设置。

要直接向成员提问，在输入框中输入 `@` 并选择成员。可按姓名或 ID 筛选，按 `Enter`、`Tab` 或点击确认。选择器用 ID 区分同名成员。也可以用完整的 `@name` 或 `@id` 开头。

你的消息显示在右侧，上方标有 **你**。主持人的消息显示在左侧，标有 **AI 主持**。你发布的结论会在 **你** 旁加上 **人工主持** 标记。长回复可就地展开，图片或 Mermaid 图可打开细看。**成员面板** 在聊天旁列出参与者。选择成员可查看每项任务的内容、时间、输出和工具活动。编辑器较窄时，可以从标题区打开面板。**协作** 可调整回复的显示长度。两轮之间可以邀请其他角色。

打开 **群记忆** 可以查看成员可用的近期公开发言和答复。将决定或约束置顶，可以在近期窗口之外继续共享。新会议默认共享最近 12 轮，也可以在面板中改为 30 或 50 轮。新邀请的角色使用同一份群记忆。任务详情显示成员收到的历史轮数和置顶笔记数量。

对话上方的置顶条预览前三条笔记。点击该条可打开 **群记忆**。

选择 **执行 Graph**，可按时间顺序查看各成员泳道中的任务记录。矩阵统计同一轮内相邻发言人之间的交接。选择节点、交接次数或回复的作者，即可在成员面板查看分派内容、时间、所用群记忆、工具调用和 Markdown 输出。

暂停共享后，笔记仍可在面板中查看。成员会收到当前问题、本次分派和本轮发现。选择 **清空群记忆** 后，下一轮从新的上下文开始。早先的消息和任务记录仍可从会议记录或 Markdown 导出中查看。

选择 **导出记录** 可将完整的归档对话、任务分派和录下的工具详情保存为 Markdown，其中包含较早的分页记录。在别的项目中查看某场会议时也可以导出。

在结论卡片上选择 **交给 Agent 继续…** 并挑选接收者。会议所属项目会新开一个聊天，草稿带上该轮的问题、结论和可用的证据引用。检查草稿，再按需要修改下一步请求并发送。

随时输入消息就能开始新一轮。切换会议或打开文件时，已经开始的讨论会继续进行。侧栏会标记后台那些需要授权的会议。**停止** 会结束当前显示的一轮，关闭会议标签页会停止该项目正在进行的讨论。FiveLeaf 将已接收的消息按项目目录和主题分组，保存到本地应用数据目录。重新打开群组会恢复对话记录和设置，等待你的下一条消息。通过 **更早的消息** 可以阅读近期模型上下文以外的内容。清除该群已保存消息前，**清空对话** 会请求确认。

邀请记录绑定所选的 Agent。即使角色被移除、改绑，或对应 Agent 被停用，先前的发言仍可按原名称读取。

<a name="agent-plugins"></a>

## Agent 插件

在 **设置 → 插件 → Agent** 中按名称搜索、安装并启用 Agent 插件。也可以用命令行安装，例如 `ff plugin install agent-omp`。安装后，已有的插件设置和角色继续使用相同 ID。见[启动命令](PLUGINS.zh-CN.md#acp-agent-servers)。

FiveLeaf 找到本地 Agent CLI 和对应的启动程序后才能打开插件开关。安装警告中提示的命令，再通过 **插件操作 → 重新加载插件** 重新检查。

| 插件 | 连接前的准备 |
| --- | --- |
| **Pi Agent** | 安装 Node.js 22 或更新版本以及 Pi。在 Pi 中登录并选择模型。 |
| **OMP (Oh My Pi) Agent** | 安装 `omp`，配置模型提供方，并确认当前版本提供 `omp acp` 命令。 |
| **DeepSeek TUI (DSH) Agent** | 安装 `dsh`，配置 `dsh --profile acp` 使用的模型提供方。 |
| **Codex Agent** | 安装 Node.js，用 Codex 自带的 CLI 登录。 |
| **Claude Agent** | 安装 Node.js，用 Claude Code 自带的 CLI 登录。 |
| **Gemini CLI Agent** | 安装 Node.js 20 或更新版本。Gemini CLI 0.68.0 支持文档所述的 Google Cloud / Code Assist 组织登录、Gemini API 密钥和 Vertex 配置。请遵循该版本的账号要求，个人 Google 账号的登录支持取决于这些要求。 |
| **Qwen Code Agent** | 安装 Node.js 22 或更新版本。以交互方式启动 Qwen Code 0.27.3，使用 `/auth` 配置支持的订阅登录或 API 提供方。 |
| **OpenCode Agent** | 从官网下载 OpenCode，确保 `opencode` 在 `PATH` 中。启动后用 `/connect` 配置模型提供方，再用 `/models` 选择模型。 |
| **Kimi Code Agent** | 安装 Kimi Code，用它的 CLI 登录，并确认 `kimi acp` 命令可用。 |

各 Agent 通过自己的 CLI 登录并配置模型访问。Pi、Codex 和 Claude Code 在首次连接时下载固定版本的 Node.js 适配器。其余插件直接运行已安装的 CLI。如果 Codex 在初始化阶段断开，同时 npm 报告 `_npx` 下缺少 `package.json`，请更新 Codex 插件并重连。若是固定到 `2.6.0` 的自定义 Agent，请将适配器参数改为 `@agentclientprotocol/codex-acp@2.7.0`。

这些预设参考了 [ACP 官方登记库](https://github.com/agentclientprotocol/registry)、[Gemini CLI 0.68.0](https://github.com/google-gemini/gemini-cli/tree/v0.68.0)、[Qwen Code 认证](https://github.com/QwenLM/qwen-code/blob/v0.27.3/docs/users/configuration/auth.md)、[OpenCode ACP](https://opencode.ai/docs/acp/)、[OpenCode 模型提供方](https://opencode.ai/docs/providers/)和 [Kimi Code](https://github.com/MoonshotAI/kimi-code)。

<a name="use-pi"></a>

## 使用 Pi

安装 Node.js 22 或更新版本及 Pi，在 Pi 中登录并配置模型。安装 `agent-pi`，并在 **设置 → 插件** 中启用 **Pi Agent**。插件运行 `npx -y pi-acp@0.0.34`。如果 Pi 在应用的 `PATH` 之外，请在 FiveLeaf 的环境中将 `PI_ACP_PI_COMMAND` 设为可执行文件的绝对路径。已有的自定义 Pi Agent 及角色也可以继续使用。

在聊天中选择 Pi，再从输入框里的模型选择器选取模型。要保存某个角色的默认模型，请在 **设置 → Agent → 角色列表** 中编辑角色，选 **Pi**，并选择一个已公布的 `provider/model` 格式的模型 ID。凭据保存在 Pi 自己的配置里。

Pi 在会话设置完成、模型改变和回复完成后上报上下文用量。指示器随这些上报更新，更新频率以这些事件为准。

Pi 的内置工具遵循 Pi 自己的规则。适配器将 Pi 扩展的确认请求转成 ACP 权限卡片。内置工具是否需要批准由 Pi 管理。

Pi 的确认卡会显示问题，以及本地化后的 **是**、**否** 选项。点 **请求详情** 可以查看该问题背后的数据。工具请求会显示命令或文件位置，需要更多信息时也会显示详细输入。对今后的请求同样生效的选项单列一行。

可选的冒烟测试使用真实 Pi 和模型提供方、隔离的 Pi 配置及只用于测试的权限扩展。显式传入 `-tags piintegration` 和 `-run '^TestPiAgentLiveWorkflow$'`，并将 `FIVELEAF_PI_SMOKE_CONFIG` 指向 JSON 文件。该文件提供 `model`、进程 `env` 和可选的 `alternateModel`。配置的提供方要能够使用这两个模型。测试扩展必须对写入 `pi-smoke.txt` 的请求调用 `ui.confirm`，并拦截其余工具。测试覆盖注册、连接、模型切换、上下文用量上报、回复、后续上下文，以及从编辑器返回同一聊天处理待授权请求。

<a name="use-another-adapter"></a>

## 使用其他适配器

打开 **设置 → Agent**，也可以在命令面板中选择 **配置 Agent…**，再选择 **添加自定义 Agent…**。填写名称和可执行文件路径或命令名。每个参数单填一项，环境变量分别填写名称和值。选择 **ACP** 或 **CLI**，也可以指定工作目录、能力标签和回复超时。比如，已安装的 OpenCode 使用 ACP，命令为 `opencode`，参数为 `acp`。单次请求式的 Claude CLI 使用 CLI 协议，命令为 `claude`，参数为 `--print`。保存后即可在 Agent 菜单中选择。

表单会分配一个未使用的 ID。编辑时继续使用该 ID，移除定义后可 **撤销**。保存时会合并这期间改过的其他定义。若同一个定义在表单打开期间被更改，会报告冲突。保存只写入配置。已有的插件覆盖项也可编辑，若 ID 与插件提供的 Agent 匹配，会显示相应标记。

高级配置可以选择 **在 JSON 中编辑**。等效的用户设置如下。

```json
{
  "agentServers": {
    "opencode": {
      "name": "OpenCode",
      "command": "opencode",
      "args": ["acp"],
      "capabilities": ["code", "reasoning"]
    },
    "claude-cli": {
      "name": "Claude CLI",
      "protocol": "cli",
      "command": "claude",
      "args": ["--print"],
      "workingDirectory": ".",
      "capabilities": ["code", "reasoning"],
      "timeoutSeconds": 120
    }
  }
}
```

`command` 是可执行文件，`args` 是参数数组，进程直接启动。如果图形界面进程的 `PATH` 中找不到适配器，请用绝对路径。可选的 `env` 项会覆盖继承的环境变量。凭据应留在适配器自身的凭据存储中。可执行程序定义可在用户设置中添加。已启用的插件可以声明 `contributes.agentServers`，见[插件文档](PLUGINS.zh-CN.md#acp-agent-servers)。

省略 `protocol` 时沿用 ACP 兼容行为。CLI 模式将按格式整理的近期消息提示词送到标准输入，读取标准输出，并在失败时读取限量的标准错误。接收末尾提示词参数的 CLI 可设为 `promptArgument: true`。程序须支持非交互式请求，并在回答后退出。`timeoutSeconds` 可填 1–3600 秒，`0` 表示使用默认设置。ACP 单聊默认持续等待回复，CLI 和圆桌会议默认超时为 120 秒。在 Unix 上，取消 CLI 任务或任务超时会终止整个进程组，包括子进程。

工作目录留空时使用项目目录，相对路径也以项目目录为基准。对 ACP 而言，这只改变进程目录，ACP 会话和编辑器文件回调仍以打开的项目为根目录。能力标签影响选择发言者的规则，编辑器权限另行处理。设为 `disabled: true` 会暂停参与并断开正在运行的 Agent。

Agent 设置里的 **导入…** 和 **导出…** 可交换 JSON 配置。

```json
{ "version": 1, "agentServers": { "claude-cli": {
  "name": "Claude CLI", "protocol": "cli",
  "command": "claude", "args": ["--print"]
} } }
```

导入时会校验整个文件，合并新的 ID，并接纳等效的既有定义。ID 有冲突时会拒绝整个文件。导出包含自定义定义、插件覆盖项及环境变量值，输出文件使用私有权限。导入只更新配置。

仅含 Agent 的导出使用 `version: 1`。绑定 Agent 的命名角色使用 `version: 2` 和 `agentRoles`。预设角色的覆盖使用 `version: 3` 和 `agentRolePresets`。包含跟随当前 Agent 的命名角色时使用 `version: 4`。FiveLeaf 可导入这四个版本。所有映射都在一次更新中合并。Agent ID、角色名或内置角色覆盖任一发生冲突，都会拒绝整个导入。导入或导出前，请保存或取消未提交的 Agent 或角色表单。

修改正在使用的定义或停用其插件会断开对应适配器，包括后台项目里的连接。重连时可以继续用原草稿。已有的终端 Agent 会话会留在 **Agent 会话** 中，仍然可以恢复。

<a name="add-code-and-review-comments"></a>

## 添加代码和审阅评论

- 标签页和输入框显示该聊天的 Agent 图标，包括由角色选择 Agent 的情况。Agent 未提供已知图标时，聊天使用机器人图标。接收代码选区的聊天会在图标后显示实心标记。切换聊天标签页或聚焦另一个聊天分栏，可以移动标记。回到编辑器后，上次聚焦的聊天仍是接收方，即使有两个聊天使用同一个 Agent。
- 右键点击选中的代码，再选 **将选区添加到 Agent**，可将原文、文件路径和行号放进草稿。没有选区时，编辑器会提供 **将文件添加到 Agent**，可附加整个文件，包括未保存的改动。
- macOS 上按 `Option+Cmd+L`，其他平台上按 `Shift+Ctrl+L`，可添加选区。没有选区时添加当前行。在文件浏览器里也可以对文件选择 **将文件添加到 Agent**。文件仍在加载时，要等加载完成再发送。
- 在差异视图中选择若干行，并用 **将选区添加到 Agent** 把新增行、删除行及来源信息一起带入草稿。
- 在聊天中，可以在命令面板里使用 **将选区添加到 Agent** 或 **将文件添加到 Agent**，添加最近聚焦的编辑器或差异视图中的上下文。
- 在审阅工具栏或命令面板中选择 **将审阅添加到 Agent**，可把审阅评论放入草稿。也可以选择 **发送到终端**。

以上操作用来准备草稿。点击 **发送** 才会提交。上下文以纯文本发送，其中包含路径和围栏代码块，也兼容未声明内嵌资源支持的 Agent。草稿上限为 2 MiB。对话记录每条消息最多显示 32 KiB，并会明确标记被截断的预览。

<a name="review-changes"></a>

## 审阅改动

工具活动会显示进度和 Agent 报告的文件。点击一个文件可在编辑器里打开只读的改动前后对照，即使项目没有 Git 仓库也可以使用。该视图支持选行和审阅评论。暂存、丢弃和接受改动属于工作区 Git 差异的操作，快照视图只用于对照。

通过编辑器写文件时，FiveLeaf 会在准备写入时捕获改动前的快照，包括用户已经保存的变更。Agent 报告的差异使用它提供的文本，也可能只是提议。继续应用改动前，请核对当前文件。多次写入可以各自保留快照。重启后的 Git 标签页恢复流程不包含这些快照标签页。

**Git → 审阅工作区变更** 打开现有 Git 差异，显示当前已暂存和未暂存的改动，并提供改动块操作及审阅评论。它涵盖工作区的所有改动，包括聊天之前已经产生的改动，以及由适配器工具直接修改的内容。

<a name="navigate-code-during-review"></a>

## 审阅时导航代码

在差异视图中选择一个符号。使用默认键位时，可按 `F12`，也可以在右键菜单中选择 **转到定义**，或在 macOS 上按住 `Cmd` 点击，在其他平台按住 `Ctrl` 点击。右键菜单的 **显示悬停信息** 会展示语言服务器为同一符号提供的信息。和普通编辑器一样，需要先启用对应语言服务器插件并安装它依赖的服务。其他键位方案使用各自设置的定义导航和悬停提示快捷键。

行内和并排差异视图均支持导航，包括 Agent 快照。查询在当前工作区进行，使用编辑器内尚未保存的内容。选中旧版本中的行时，FiveLeaf 仅在该行内容相同且能唯一对应到当前文件时使用它。若该行已被编辑或删除，审阅视图会保持打开，并提示在当前文件中选择符号。语言服务器收到的是当前文档，旧版本的文本只用于定位。打开定义后仍可回到审阅标签页继续查看评论。

<a name="supported-protocol-and-boundaries"></a>

## 支持的协议和边界

客户端使用稳定版 ACP v1，通过以换行分隔消息的标准输入输出 JSON-RPC 通信。它支持创建会话、适配器声明的 `session/load` 和 `session/resume`、流式文本和思考内容、工具、计划、适配器提供的模式、Agent 管理的登录、权限请求和取消操作。Agent 斜杠命令可以在输入框里输入。MCP 服务器配置及从登记库自动安装目前超出客户端的支持范围。

读取文件时使用当前编辑器缓冲区。文件已有未保存的改动或正在等待保存时，写入请求会被拒绝。FiveLeaf 在后台准备临时文件，再在编辑器主线程检查原先打开的文档是否仍在同一路径、用户是否进行了新的编辑。检查通过后才会原子替换文件。准备写入时，如果用户继续输入、关闭文档或执行 **另存为**，会拒绝 Agent 的写入并保留用户文本，排队的用户保存操作随后可以继续。文件回调要求会话已知，访问范围位于解析后的工作区内，并拒绝 Git 元数据和非文本文件，同时限制大小。这些检查适用于编辑器的回调。适配器以普通本地进程运行，可以使用自己的工具。

客户端声明的能力不包含执行终端命令和通过终端登录。Agent 自带的终端工具可以按其自身规则使用。远程 SSH 工作区会明确提示需要打开本地文件夹。错误和被拒绝的权限请求会保持可见。

CLI 和 ACP 都实现独立于界面的 `internal/roundtable.Adapter` 接口，方法为 `Call(context.Context, []Message) (Message, error)`。以后可以为 HTTP 或 gRPC 适配器实现同一接口。调度和子进程 I/O 在界面线程之外运行。配置以 JSON 持久化，对话记录目前存于内存。SQLite 历史、LLM 评判和 token 预算属于可选扩展，此版本尚未启用。

自动检查会运行真实的辅助 CLI 和 ACP 进程，覆盖分派、超时、取消、权限、文件修改和对话隔离。付费模型请求和外部账号验证只在显式启用上面的可选真实连接检查时进行。

参考资料见 [ACP 协议](https://agentclientprotocol.com/protocol/v1/initialization)、[Zed 外部 Agent](https://zed.dev/docs/ai/external-agents)和 [Zed Agent 面板](https://zed.dev/docs/ai/agent-panel)。
